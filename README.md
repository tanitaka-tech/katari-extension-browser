# ブラウザ（com.tanitaka.browser）

[Katari](https://github.com/tanitaka-tech/Katari) エディタ内に**ブラウザタブ**を開くエディタ拡張。
URL バー + ネイティブ子 webview（`ui.webview({ native: true })`、Katari ADR-0076）で任意の
https ページを Dock タブとして表示する。ネイティブ webview はトップレベル文書扱いなので、
`X-Frame-Options` で埋め込みを拒否する google.com / MDN などもタブ内に表示できる。
タブは他のビューと同様にドック / フローティング / OS ウィンドウ化できる。

必要な Katari: **0.2.0 以降**（`min_app_version`）。

## インストール

いずれかの方法で入れる。初回はエディタの承認ダイアログで有効化する。

1. **URL から追加**: Katari のメインメニュー「拡張 → 拡張を管理...」を開き、
   「URL から追加」欄にこのリポジトリの URL を貼って「追加」。
2. **プロジェクト同梱**: このリポジトリの中身を
   `<project>.ktrtproj/Extensions/com.tanitaka.browser/` に置き、管理ウィンドウの「リロード」。

## 使い方

- メインメニュー「拡張 → 新しいブラウザタブ...」または `CmdOrCtrl+Alt+B`。
- ツールバーは `← → ⟳ [URL バー] ★ 🕘 ＋`。
- URL バーに入力して Enter で移動。scheme 省略時は `https://` を補完する（http は不可）。
- URL バーとタブ名はページ側の遷移（リンククリック、SPA の `pushState`）にも追従する。
- 「＋」でこのタブの隣に新しいブラウザタブを開く。

## 権限（`webview:*` は使う直前に尋ねる）

この拡張が要求する権限は `webview:*`（任意の https サイトをエディタ内に表示する）だけ。
ただし**承認時には要求しない**。任意の https を丸ごと許すのは承認画面で判断するには広すぎるので、
`optional_permissions` として宣言し、**最初にページを表示する直前**に
`katari.permissions.request()` で尋ねる（Katari ADR-0084）。

- 許可するまで、タブにはページの代わりに「許可する」ボタンだけが出る。
- 許可は管理ウィンドウの詳細ペインから**いつでも取り消せる**。取り消しは即座に効き、
  次にタブを開く / URL バーで移動した時点でページが外れて再び許可を求める画面に戻る。
- 拡張がページの内容を読んだり、ページがエディタ本体へ到達したりすることはできない
  （ネイティブ webview は Tauri IPC 非注入）。fetch（`net:`）権限は持たない。

## 設定

**エディタ設定 → 拡張 → ブラウザ**に、この拡張が `contributes.configuration` で宣言した
フォームが出る（描いているのはエディタで、拡張は値を読むだけ）。編集は即座に反映される。

| 設定 | 既定 | 意味 |
|---|---|---|
| ホーム URL | `https://developer.mozilla.org/` | 「新しいブラウザタブ...」と「＋」で開く初期ページ。https のみ |
| 履歴の保持件数 | `20` | タブ 1 つあたりの訪問履歴の上限（0〜100）。`0` で履歴を取らない |
| ステータスバーにタブ数を出す | オン | ステータスバーの常駐表示（下記） |

## お気に入りメニュー（★）

ツールバーの「★」で開閉するポップアップ（ページを押し出さず、ページの上に重なる）。
現在のページがどちらかに登録済みなら「★」、未登録なら「☆」になる。
外側クリック / ページ内クリック / Escape で閉じる。

- **エディタお気に入り / プロジェクトお気に入り**のチェックボックスで、現在のページを追加・解除。
- その下にお気に入り一覧（エディタ → プロジェクトの順）。**行クリックで移動**、`×` で削除、
  ドラッグで並べ替えできる（本体インスペクタと同じリスト UI）。
- 一覧は **ページタイトル**で表示する（登録時のタイトルを保存。未取得のものは URL 表示のまま
  だが、そのページを一度開けば自動で名前が付く）。

保存先:

- **エディタ設定 → 「ブラウザお気に入り(共通)」**: すべてのプロジェクトで共有（`settings.json`）。
- **プロジェクト設定 → 「ブラウザお気に入り」**: 現在のプロジェクトに保存（`project-settings.toon`、
  git 管理・配布同梱）。

各設定タブでは `＋` で既定 URL（`https://example.com/`）の行を追加し、**行をクリックして
名前（表示タイトル）と URL をその場で編集**する。名前を空にすると URL 表示に戻る。
`×` で削除、ドラッグで並べ替え。

> お気に入りだけ `contributes.configuration` ではなく `contributes.settings` +
> `katari.storage` に残しているのは、宣言的設定の型が
> `string` / `number` / `boolean` / `select` / `secret` の**スカラだけ**で、
> 並べ替えできるリストを表現できないため。スカラ設定（上の表）は宣言側へ移してある。

## 履歴メニュー（🕘）

ツールバーの「🕘」で開閉するポップアップ。**ブラウザタブごと**の訪問履歴（新しい順、
「履歴の保持件数」設定の件数まで）を**ページタイトル**で出し、行クリックでその URL へ移動、
`×` で 1 件削除、「履歴を消去」で全消去する。履歴はタブ状態として保存されるので、
エディタを再起動してタブが復元されたときも残る。

## ステータスバー

`katari.status.set()` で**登録済みのお気に入り件数**をステータスバーに常駐させる
（クリックで新しいブラウザタブが開く）。「ステータスバーにタブ数を出す」設定で切れる。

> 「開いているタブ数」ではなくお気に入り件数を出しているのは、拡張 API に
> **ビューが閉じられた通知が無い**ため（ホストの `viewClosed` は Worker ランタイムが
> 内部で処理して終わり、`katari.window` からは観測できない）。開いた数は数えられても
> 閉じた数を引けないので、タブ数は必ず実際より多くなる。件数は storage から常に正確に出せる。

## 多言語化

拡張が自分で描く文言は `l10n/ja.toon` / `l10n/en.toon` に置き、`katari.t()` で引く
（Katari ADR-0084）。エディタの言語 → `en` → キーそのもの、の順にフォールバックする。
言語を足すときは `l10n/<locale>.toon` を追加する。`ja` のキーは `en` にも必ず置くこと
（`main.test.ts` が検査する）。

## 制限

- タブ内ネイティブ webview は **main ウィンドウのタブ内でのみ**表示できる。OS ウィンドウへ
  切り離す（tear-out）と iframe にフォールバックし、そこでは `X-Frame-Options` 拒否サイト
  （google.com / MDN 等）は空白になる。
- 履歴はこの拡張が観測した遷移（URL 変化）のみで、webview 自身の履歴スタックとは別物。
  `←` / `→` はブラウザ本来の履歴を辿る。
- ネイティブ webview は最前面に描くため、ダイアログ / コマンドパレット表示中は自動で隠れる
  （トースト等が隠れることもある）。★ / 🕘 のポップアップは隠さず、重ならない位置へ
  webview が縮んで避ける。
- 開いているタブの数は拡張からは分からない（上記「ステータスバー」）。

## 開発

```sh
pnpm install
pnpm run typecheck   # 配布物（main.ts）とテスト側をそれぞれ型検査
pnpm run test        # エディタを起動せずにロジックを検証
pnpm run check       # 上の両方（CI と同じ）
```

ビルド手順は不要（Katari が esbuild-wasm で `.ts` をそのままバンドルする）。

Katari 本体（`examples/extensions/`）からコピーしている**ベンダーファイル**:

| ファイル | 用途 |
|---|---|
| `katari-ext.d.ts` | `@katari/ext` の型定義。`tsconfig.json` の `paths` がここを向く |
| `katari-ops.d.ts` | `katari.ops.invoke()` / `katari.edit()` の引数型（Katari 本体から自動生成） |
| `katari-ext-test.ts` | テストキット（`katari` / `ui` のモック） |
| `katari-ext-shim.ts` | テスト時に `@katari/ext` の実体になるシム（`vitest.config.ts` が alias する） |

本体を更新したらこの 4 つを取り直す。`katari-ext-test.ts` だけは**ローカルで足した差分**が
あるので、上書きではなくマージすること（該当箇所には「ローカル追加」とコメントしてある）:

- `katari.t()`（l10n の引き当て）
- `katari.permissions.has/request` を許可済み集合で動かす（upstream は常に `true`）
- `renderSettings()`（`katari.settings.panel()` で登録したパネルを描画させる）

### 対応する Katari 側の変更

- ADR-0061 エディタ拡張システム
- ADR-0076 拡張の webview ノード
- **ADR-0084 拡張プラットフォームの強化**（配布メタデータ / 任意権限 / 宣言的設定 /
  l10n / ステータスバー / テストキット）
